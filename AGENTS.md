# Project conventions

Full details live in `README.md`, keep both in sync when conventions change.

- **Identity/metadata**: edit `lib/site.ts` only; layouts, robots, sitemap and manifest import from it. Canonical origin comes from `NEXT_PUBLIC_SITE_URL`.
- **Landmarks**: `app/layout.tsx` owns `<main id="content">` plus the skip link; `lib/site-footer.tsx` owns `<footer>` and renders it on every page except `/` (the business card already shows the contact links there). There is no site-wide header/navbar; contact links live on the front of the home-page business card, its reverse introduces the developer and technical stack (flip on click), and the full work index lives on `/projects`. Pages must NOT render their own `<main>`.
- **Color/contrast (WCAG AA)**: never use `text-foreground/<opacity>` for text, it fails contrast. Use the `text-muted` token (4.95:1). If `--background`/`--foreground` change, re-verify `--muted` contrast ≥ 4.5:1.
- **Area inks**: `--accent-software` (TypeScript blue) and `--accent-security` (terminal green) are the two area inks; `--accent` (antique gold) is the neutral fallback for unmarked surfaces and general furniture. All three are decorative furniture only, never body text. Pages pick an area by carrying `.area-software` or `.area-security`, which set `--area-accent`; every consumer reads `var(--area-accent, var(--accent))` (or the `area-accent` utility) so unmarked subtrees — the home card, `/privacy`, the footer — keep the gilt. `/projects` sets the class per card and per filter chip, so both inks appear at once. New accent-coloured furniture must use `--area-accent`, not `--accent` directly.
- **Theming**: never hardcode hex values in components, use the `globals.css` tokens (`--panel`, `--panel-sunken`, `--code-*`, …) and their utilities (`bg-panel`, `text-(--code-tag)`). Dark mode is opt-in per page: the page root carries `project-surface` and dark tokens are scoped to `html.dark:has(.project-surface)`, so the home business card and `/privacy` stay on paper. Dark is the default: the `dark` class on `<html>` is the source of truth, applied pre-paint by the inline script in `app/layout.tsx` from `localStorage.theme`, else unless `prefers-color-scheme: light` is set. `lib/theme-toggle.tsx` is the control, a single disc morphing sun/moon through CSS geometry properties (`.theme-morph-*`).
- **Motion**: shared easing is `cubic-bezier(0.22, 0.61, 0.36, 1)` — ease-out, never overshoot. Utilities live in `globals.css`: `.reveal` (scroll-driven section entrance), `.project-card-stagger` (`--i` set per card), `.link-rule` (underline that wipes in), `.cs-nav-thumb`, `.chip-blueprint` (the Software Development filter chip's hover grid; the Cybersecurity chip's glyph rain is canvas-driven in `app/projects/matrix-rain.tsx`). Every one needs an explicit `prefers-reduced-motion` escape, and scroll-driven animations must be wrapped in `@media (prefers-reduced-motion: no-preference)` — the global `animation-duration` clamp does nothing for a `view()` timeline, since progress comes from scroll position rather than time.
- **A11y**: one `<h1>` per page, sections labelled with `aria-labelledby`, descriptive `alt` text, accessible names on videos, external links announce new tabs. Keep `:focus-visible` and `prefers-reduced-motion` styles in `globals.css` intact.
- **Privacy (GDPR)**: no cookies, no analytics, no third-party requests (fonts are self-hosted). Adding any tracking requires a consent mechanism and a `/privacy` update.
- **Tech-stack icons**: technology labels map to the local `tech-stack-icons` subset in `lib/technology-badge.tsx`. When adding a catalog icon, add its ID to `scripts/generate-tech-stack-icons.mjs` and run `npm run generate:tech-icons`; do not edit the generated file. Supplemental icons use locally bundled `react-icons` (Simple Icons brand marks and Tabler representative symbols), mapped in `lib/technology-badge.tsx`.
- **Static export**: `output: "export"` in `next.config.ts`; `npm run build` emits `out/` for nginx (reference config: `deploy/nginx.conf`). No server-only features (server actions, `headers()`/`redirects()`/`rewrites()` in config, request-reading route handlers, default `next/image`). Metadata routes (`icon.tsx`, `apple-icon.tsx`, `robots.ts`, `sitemap.ts`, `manifest.ts`) need `export const dynamic = "force-static"`.
- **Security**: headers live in `deploy/nginx.conf` (a static export can't set them from `next.config.ts`). CSP allows inline scripts because rendering is static; switch to nonce-based CSP (`proxy.ts`) if going dynamic.
- **Routing metadata**: add new public pages to `app/sitemap.ts`.

- **Project content**: `app/projects/data.ts` holds unified metadata (`areas`, `projectType`, and optional `caseStudy`). Software showcases retain their existing layout; security write-ups use typed blocks in `content/case-studies/` and the shared case-study renderer. Keep evidence local and distinguish observations from proposed tests. See README.md for the authoring workflow.
